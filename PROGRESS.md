# NoWaste progress

## How to run (short)

Full steps for a new laptop are in README.md.

1. `npm ci` (root only)
2. Copy `server/.env.example` to `server/.env` and `app/.env.example` to `app/.env`
3. `npm run db:up`, then `npm run migrate` and `npm run migrate:test`
4. `npm test` and `npm run lint`
5. `npm run dev:server` in one terminal, `npm run dev:app` in another, then scan the QR code with Expo Go

10. **SDD C-24 Map View:** the skeleton task asked for adapter folders C-20 to C-26, but the SDD places C-24 inside the app. No server folder was created for C-24. Confirm.
11. **Arabic texts:** all Arabic strings in app/src/i18n/ar.json should be checked by an Arabic speaker on the team.
12. **npm install scripts:** npm 11 blocks install scripts that are not approved (esbuild, unrs-resolver, @parcel/watcher). Everything works without them so far. Should the team approve them?
13. **npm audit:** 4 high-severity advisories come from Expo's own CLI (node-forge). `npm audit fix --force` would downgrade Expo, so it was not run.
14. **SRS 4.1.2 says registration "creates the account and logs the consumer in".** Login is US-04 (turn 3), so this turn shows an "Account created" screen instead. Should US-04 log the consumer in straight after registration?
15. **CLAUDE.md says rule values come from the settings table, but the password rule (D-11) lives in shared code**, because the app must check it before sending and the turn asked for one shared validator. Accept this, or move the minimum length to settings and add an endpoint to read it?
16. **Maximum password length:** bcrypt only uses the first 72 bytes of a password. The SRS sets no maximum. Add one?
17. **D-14 in standalone builds:** in a development or production build on a phone whose system language is Arabic, React Native may start in RTL by itself. The app sets its own direction on every screen, but this must be checked once the team makes a development build.
18. **`shared/index.js` is not linted** (ESLint runs only in app/ and server/). It now has unit tests (server/tests/shared.test.ts). Add a lint config for shared?
19. **Busy button contrast:** while "Creating your account…" shows, the faded button label is about 2.0:1. Inactive controls are usually exempt from the 4.5:1 rule; confirm with the team.
20. **SQL in a test helper:** server/tests/helpers/database.ts truncates and counts users with SQL, outside server/src/data. Accept for tests?
21. **TalkBack extra announcements (N-7, 2026-10-24, elinx9, Android 16):** TalkBack reads field names correctly but announces text formatting such as "55 pixels" and "text color grey" before NoWaste texts (first report also mentioned "Language for accessibility"). It does not happen on the Expo Go home screen. The Element Inspector was not available in the developer menu. No app label contains such information. Suspected cause (not confirmed): React Native puts text size and colour into formatting spans that TalkBack describes. Decide: investigate the text styling (needs a code change and approval) or retest TalkBack in a development build. Also: should the server status line on the Welcome screen (D-21) stay visible to users and TalkBack, or only in development?
